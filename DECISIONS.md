# DECISIONS.md — Decisions made while building Beanstack

Recorded so a later session (or a reviewer) can see why things are the way they are, without re-litigating them.

## 2026-11-04 — Foundations

- **Styling: custom CSS instead of Tailwind.** The prompt allows any styling approach (Tailwind is welcome, not required). A small custom CSS design system (variables, light/dark themes, responsive grid) was chosen for build reliability and to keep the initial bundle simple. The design system is coherent and applied consistently; switching to Tailwind later is possible but not required.
- **Content location: `content/` at repo root, not `src/content/`.** This makes "content is completely separate from UI code" literal and visible. Vite lazy-loads Markdown bodies from `/content/**/*.md` with `?raw`, so each topic becomes its own chunk.
- **Content index: generated JSON, committed.** `scripts/build-content-index.mjs` scans `content/` and writes `src/generated/content-index.json`. The app imports that index for navigation/search; topic bodies are lazy-loaded separately. The generated file is committed so a plain `npm install && npm run build` works without a prebuild step, and so reviewers can inspect the index. Never edit it by hand — regenerate it.
- **Structured data as JSON, prose as Markdown.** Topics and cheatsheets are Markdown with frontmatter (preferred format). Interview questions and practice items are JSON, because their fields (options, answer index, follow-ups, Leitner state) are structured data, not prose. Both live in `content/` and are validated by the same script, satisfying "cheatsheets, interview material and practice data all live in this same content system".
- **Tracks grouped by domain, but tracks are the primary navigation unit.** Domains (Java Ecosystem, Frontend, Data, Design, Coding, Platform, Quality, Career) are metadata in `tracks.json` for future grouping; the sidebar and Learn pages navigate by track, which keeps navigation clean as the app grows.
- **Framer Motion used only for a subtle page fade.** No elaborate animations. Reduced-motion preference is respected via Settings and CSS.
- **Syntax highlighting: highlight.js + react-markdown + remark-gfm.** Well-maintained libraries; no custom Markdown parser was written, as required.
- **State: React Context + LocalStorage only.** No Redux/MobX. Storage key `beanstack-user-data-v1`, schema version 1. Export/import validates referenced ids against the current content index.
- **Section ids are globally unique.** This simplifies validation of prerequisites/related references and section lookups. Track + section together still define the URL.
- **Placeholder tracks show planned sections, not empty pages.** Every placeholder track has sections with `plannedTopics`, so its page is useful and clearly marked "Coming Soon".
- **Main bundle warning accepted for v1.** The production build warns about an 820 KB main chunk (React + router + markdown + highlighting). Content chunks are already split per topic. Vendor chunk-splitting is a polish item in PROGRESS.md, not a blocker, because the warning does not fail the build and initial content load is lazy.

## Content decisions (sample batch, 2026-11-04)

- Sample content proves every feature end to end: 13 topics (6 Core Java, 3 Advanced Java, 4 Spring & Spring Boot), 2 cheatsheets, 11 interview questions, 16 practice items, 3 learning paths.
- Java version target: current LTS Java (21 at time of writing, with 8/11/17/21 differences called out where interviews ask about them). Spring Boot: current stable, with auto-configuration imports path noted as in current Spring Boot.

## Critic audit run (2026-11-04 — navigation, robustness, tone; NOT pushed)

- **Topic URL segments are validated.** A topic id alone no longer renders at a wrong track/section address; a mismatched URL now shows the in-place not-found with a link to the topic's correct address.
- **Search now really covers MCQs.** The original prompt promises search across topics/questions/MCQs/cheatsheets, but Search and the palette only covered the first three. Practice MCQs are now included (linking to `/practice?tab=mcq`); Search page track labels now use track titles, not raw ids, and its empty-query state gives guidance instead of a blank list.
- **Trailing `## Version Differences` sections kept as-is.** 10 topics have one after Revision Summary. It does not break the required section order and carries genuinely useful version information; folding it into Revision Summary would lose its visibility.
- **Duplicate `##` headings in one topic remain a known minor limitation.** Disambiguating DOM ids consistently across MarkdownView, TOC, and scroll-spy is riskier than the incidence justifies; no current topic is known to rely on duplicate headings.
- **LocalStorage quota-failure UI not added.** Save failure still degrades to in-memory operation silently; a toast/banner component for it would be new UI machinery for an edge case that sanitisation/caps already make unlikely.
- **Validator hardened** (duplicate section ids across tracks, duplicate cheatsheet/path ids, topic order uniqueness per track/section, lastUpdated presence/format, interview module/difficulty enums, practice type/difficulty enums, MCQ/output answerIndex range, flashcard front/back presence). Current content passes all new checks, so these are hardening, not live bug fixes.
- **Import philosophy unchanged:** import stays reject-on-unknown-id with a clear recovery message, while local storage stays lenient-repair. Silently dropping unknown ids on import would hide data loss.

## Desktop Modules interview import (2026-11-09)

- **Copyright rule (binding):** Faizan's Desktop `modules` files are extracted third-party PDFs (GenZ Career / courses.genzcareer.org, GoalKicker, etc.). They were used ONLY as an inventory of which topics/questions to cover. Every question and answer added to Beanstack was written fresh in Beanstack's own words, in plain easy language. No question, answer, code block, or passage was reproduced verbatim, no long passages were copied, and no source PDF URLs were included in Beanstack content. The source files themselves live only in `~/workspace/modules-source/` and must never be committed to GitHub or copied into `~/workspace/beanstack/`.
- **Dedupe policy:** same coding/stream tasks repeat in every module, and much theory repeats across experience levels. New questions were deduped within each module, against all 168 pre-existing Beanstack interview questions, and centrally across modules after the parallel per-module workers finished — 10 near-duplicates were removed centrally, keeping the lowest-module version (e.g. first non-repeated character kept in Module 2 only; OAuth2 code flow kept in Module 2 only).
- **Category mapping:** Spring Security, Kafka, Design Patterns, and Lead/non-technical questions have no dedicated Beanstack category, so they were mapped to the closest allowed category (Spring Boot / Microservices / Java / Scenario-based) or skipped. Maven/Git/Gradle and JUnit/Mockito were largely skipped in Modules 2-4 because the DevOps/Testing interview files already cover them and module files have no DevOps/Testing category.
- **Module 0 source has 7 resources, not 8,** and its handwritten-note OCR is garbled; inventory was from headings/contents lists only, nothing was transcribed. Bonus source is only resume tips + a Canva link, already covered by the existing 12 resume items, so nothing was added there.

## Small UX changes (2026-11-04 — clickable topic arrows)

- **Clickable left/right arrows, not keyboard arrow keys.** The original prompt forbids plain arrow keys for topic navigation (they conflict with scrolling and text selection). The new navigation is therefore click-only: a top prev/next bar with labelled arrows on every topic page, plus large fixed chevron buttons on very wide screens (≥1400px, where they cannot overlap the content). The existing bottom prev/next links are kept, so mobile users still have navigation. Arrows follow the existing `prevNextTopic` order — previous/next topic within the same track, not across tracks.
- **Scroll to top on topic change.** Clicking next/previous from the bottom of a long topic used to leave the new topic scrolled to the bottom. TopicPage now scrolls to the top on topic change.

## Completion run 2026-11-04 — all tracks to 100%

- **Non-Java tracks use their own primary language for code examples.** The original "Java-focused" constraint is preserved for the Java tracks and for the spirit of the rule (one language per example, no tabs/switchers/runners/playgrounds), but a Frontend topic written only in Java, or a SQL topic with no SQL, would be useless. Frontend topics use JavaScript/TypeScript/JSX, Databases use SQL (plus Java/JDBC where it illustrates Java usage), System Design uses Java for LLD and Mermaid for HLD diagrams, DSA uses Java, DevOps uses Bash/Dockerfile/YAML, Testing uses Java/JUnit/Mockito. CONTENT_GUIDE.md and README.md were updated to say this explicitly.
- **Track status is now `complete` and `comingSoon` is false for all 10 tracks.** The UI badge is driven by `comingSoon`, not by track status, so clearing that flag is what removes "Coming Soon". Java tracks were previously `draft` in tracks.json despite complete topics; they are now `complete` for consistency at 100%.
- **Interview question grouping is module → category → questions, plus browse-by-topic.** The InterviewQuestion type has no separate `group` field, so a separate question-group level was not added: it would have required a type, index-builder, and UI change, not a content-only change, and the existing module/category/topic grouping already provides the hierarchy the prompt describes (module → category/technology → questions). This is recorded as a deliberate non-change, not a missing feature.
- **Optional deeper Java topics were not added as endless scope.** The planned Java curriculum is already covered: collections deep dive covers List/Set/Map specifics, and JDBC & Networking covers JDBC/networking. Adding separate topics for every sub-area would be scope creep, not a curriculum gap.
- **Validation fix (central, not a content change in meaning):** 19 new practice items (flashcards, scenarios, coding) lacked a `prompt`/`title` field, which the validator requires. A `prompt` was added derived from the item's own `front` (flashcards) or first sentence of its `description` (scenarios/coding); no answers, solutions, or wording of the items themselves were changed.
- **Bundle note:** the generated content index is imported statically, so the main `index-*.js` chunk is ~722 KB (gzip ~215 KB), under the configured 800 KB warning limit in vite.config.ts. Topic Markdown bodies remain split per file. Splitting the index itself would be a component/architecture change and was not done in this content run.
- **JDK:** no JDK is installed in this environment and no SDK manager is present. A JDK was not installed, because that would be a system-level change to the agent VM, outside the repository scope. All new snippets were manually reviewed only; no javac verification is claimed.
